## Gaps to fix — audit-only

1. **Fix failure identity in 2×2 and CDC runners.**  
   `2×2 failure` uses `processName`/`None`, whereas Start uses `step_name`/category. `CDC runner failure` has the same mismatch. Passing the old audit ID does not repair this: the writer matches by step/sub-step. Preserve the resolved audit context and avoid duplicate failure rows.

2. **Move Success after the final status write.**  
   Applies to Capability Setup L1/L2/L3 and WFA salary/cost-saving branches. Currently a later status-write failure can follow an already-recorded Success.

3. **Resolve Generate All persistence ownership.**  
   Capability Setup Generate All records Success without a local output-write checkpoint. If PBI requires persisted completion, emit Success at the actual persistence boundary—not merely after generation. Do not add business writes as an incidental audit change.

4. **Cover early failure paths and protect failure auditing from cleanup errors.**  
   - WFA starts with `audit_enabled=False`; failures before action resolution are not audited, and its `HTTPException` handler bypasses Failed auditing.
   - Utility audit locals are initialized inside the main try; earlier failure can leave them undefined.
   - AI Identifier calls `monitor.stop_progress()` before Failed auditing; a cleanup exception can prevent the audit call.
   - Industry Map Start occurs after blob loading, so a failed load has no Start checkpoint.

5. **Make `event_time` timezone-aware on every creation path.**  
   Replace reliance on the naive model default, particularly for failure-only rows and direct CRUD creation.

6. **Fix actor fallback for nonnumeric `userId`.**  
   `The helper` performs email lookup only when the original `user_id is None`. An email-valued `userId` becomes null without fallback. **Confirmed by the in-memory check.**

7. **Warn on invalid audit timestamps instead of silently storing null.**  
   Valid timestamps normalize correctly; malformed strings currently lose `requested_time` without an explicit warning.

8. **Close history/count and uniqueness edge cases.**  
   A failure-only version can be appended while `total_runs` stays zero. Also consider enforcing the one-row identity at DB level, accounting for nullable substeps, rather than relying solely on writer locking.

9. **Do not record Success solely because a write call returned.**  
   In the Project Capability Map path, a null `updated_record` does not prevent Success. Validate the existing write result before recording audit completion.

10. **Optional completeness/naming alignment:**  
    Add intermediate audit checkpoints for the three map/utility flows and Capability Setup Generate All if required by PBI; populate analysis identity where currently available but omitted; obtain the approved Industry Map label and align remaining client-worded audit messages. **Do not rename business fields or substitute workspace for industry without an agreed contract.**
