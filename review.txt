Hi Abhilipsa, a small correction to my earlier message: the default is used. Two places in the code:

db/models.py: status = Column(String(50), nullable=False, server_default='In Progress'). When a new step/sub step row is first inserted, run_genai_audit_log does db.add(record) + db.flush() before setting status, so the INSERT uses this DB default to satisfy NOT NULL. In the same transaction it then sets the actual status from the latest run (In Progress / Success / Failed) and commits.
db/db_operations_orm.py: run_genai_audit_log(..., status="In Progress", ...). The function’s default is In Progress, and every API start checkpoint passes status="In Progress" explicitly.

So a run always begins as “In Progress”, and the DB default keeps the first insert valid. I’ll keep NOT NULL DEFAULT 'In Progress' in the migration so it matches the model.

User Story:
As a user, I want to switch between 2X2 and Fit vs Dollar views in the AI Prioritization step so that I can compare capabilities based on their fit score and cost savings opportunity.

Menu Navigation:

Analysis Library -> Analysis Library -> Step 4: AI Prioritization -> Add New AI Prioritization Entry
Analysis Library -> Analysis Library -> Step 4: AI Prioritization -> View AI Prioritization Entry

Acceptance Criteria:

Currently implemented capability selection work as it is.
Once capabilities is selected and user clicks on "Generate AI Prioritization", currently implemented 2X2 viability and feasibility chart, calculation and table should remain same.
System should page with 2X2 as a default selected view and 2X2 viability and feasibility chart, calculation and table as a default loaded view.
New Metric selection Option:
Under the AI Prioritization step, a new Metric selection option should be available with two radio buttons: 2X2 and Fit vs Dollar.

2X2 selected: Once user has selected 2X2, it should load the 2X2 viability and feasibility chart and table based on what has been already implemented.

Fit vs Dollar Selected: Once this option is selected, view should get replaced with fit vs dollar view and system should display the Fit vs Dollar chart along with the selected L1 capabilities or l2 capabilities or L3 capabilities based on which capabilities are selected.

The Fit vs Dollar chart should display:
• X-axis: High Fit Score (%) ranging from 0% to 100%.
• Y - Axis Dollar Value : The Y-axis should represent the Cost Savings Opportunity and always start at 0.

The Y-axis range and intervals should adjust dynamically based on the cost savings values of the capabilities displayed in the chart.
The Y-axis labels should use the appropriate unit—thousands (K), millions (M), or billions (B)—based on the values.
The scale should not be fixed and should accommodate the highest cost savings value. Example ranges include 0, 10K, …, 100K, 0, 10M, …, 100M, or 0, 1B, …, 100B, depending on the data.
• Date Retrieval:

The system should retrieve the Fit Score (%) and Cost Savings Opportunity ($) from the existing Cost Savings Potential data in the AI Identifier and Impact Analyzer steps and display these previously calculated values on the Fit vs Dollar graph, without recalculating them.
• Each capability should be represented by a numbered bubble based on its Fit Score and Cost Savings Opportunity.
• Bubble should contain ID associated with each capability.
• Logic to assign bubble: System should assign ID in sequential order to all selected capabilities which are being used in viability and feasibility calculation.
The chart should display four quadrants to help users compare capabilities based on their fit score and dollar value.

Bubble must contain:

ID Identifier
Position according to numeric values
Color coding based on

Capabilities who are belonging to same parent should have same color coding.

Random unique color coding should get assigned to each capability grouping (capabilities who have same parent).

For L1 capabilities , color should be unique for each capability.
When the user hovers over a capability bubble, a tooltip should display the following information:

Image
• Capability name with its L1, L2 and L3 hierarchy.
• Fit Score (%).
• Cost Savings Opportunity ($).
• Checkbox to select the respective capability to Queue Capability Double Click (Only for L3 capabilities) checkbox option should not be there in case of L1 and L2 capability.

Users should be able to select capabilities using the checkbox available in the tooltip in case of L3 capabilities only. The Capabilities Selected count should reflect the selected capabilities. (Only in case of L3 capabilities).

Fit vs Dollar Grid: When Fit vs Dollar is selected, the grid below the chart should display the following columns:
• ID
• L1 Capability Name
• L2 Capability Name
• L3 Capability Name
• Fit Score
• Cost Savings Opportunity
• Actions (With Checkbox selection option only in case of L3 capabilities): Users should be able to select capabilities using the checkbox available in the action. The Capabilities Selected count should reflect the selected capabilities.

Search, Sort and Pagination:
• Search: User should be able to use the search by inserting text and system should return the records which are matching with inserted search text.
• Sort: column ascending and descending should be implemented
• Pagination: Pagination should get implemented same as 2X2 grid.

Export to CSV
Users should be able to export the Fit vs Dollar grid data using the Export to .CSV button. The exported file should contain the corresponding capability details, Fit Score and Cost Savings Opportunity including below mentioned columns:

ID
L1 Capability Name
L2 Capability Name
L3 Capability Name
Fit Score
Cost Savings Opportunity
Business Rules:

When the user switches back to 2X2, the system should display the existing Viability vs Feasibility chart and its corresponding grid without impacting the existing functionality.
The existing Access Dimension Master and Queue Capability Double Click options should remain available in both views.
Users should be able to select capabilities (For L3 Capabilities only) from the Fit vs Dollar chart and queue them for Capability Double Click using the existing functionality.
Switching between 2X2 and Fit vs Dollar should update the chart and grid without requiring regeneration of AI Prioritization results.
Existing 2X2 Enhancement:
• For each capability, the system should retrieve the existing High Fit (%) and Cost Savings Opportunity values calculated in the previous AI Identifier and Impact Analyzer steps.
• Both values should be passed as additional context when determining each dimension score for viability and feasibility for each dimension.
• The existing inputs and context used for dimension scoring should remain unchanged. The two new values should be included alongside them, not replace them.
• The overall viability and feasibility scores should continue to use the existing calculation method, based on the dimension scores determined with the additional context.
